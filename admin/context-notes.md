# 컨텍스트 노트 — 관리자웹(admin-app)

## 이 문서의 성격 (2026-08-18 작성)

`design/context-notes.md`·`server/context-notes.md`와 달리 이 문서는 **실시간으로 작성되지 않았다**. admin-app은 2026-08-06부터 여러 세션에 걸쳐 구축됐지만 그 과정이 설계 문서에 한 번도 기록되지 않았고, 이번에 "지금까지 작업한 내역을 설계서에 모두 업데이트"라는 요청을 받고서야 사후에 정리하게 됐다.

**근거 자료**: git log(`apps/admin-app`, `apps/api/src` — 단 10개 커밋뿐, 매우 batched), 각 파일 최상단의 한국어 헤더 주석(이 프로젝트 컨벤션상 모든 신규 파일에 필수), `menuConfig.ts`에 날짜와 함께 인라인으로 남아있는 메뉴 구조 변경 결정 메모, Prisma 스키마의 인라인 주석. **아래 "결정"들 중 날짜·근거가 명시된 것은 코드에 실제로 남아있는 기록이고, 그 외 세부 진행 과정(시행착오, 오갔던 대안들)은 원본 대화가 없어 복원 불가능하다** — 추측으로 채우지 않았다.

## 구조적 패턴 (코드에서 반복 확인됨)

- **마스터-디테일 매핑 화면의 공통 형태**: 딜러사 매핑(AD-CTLG-08/AD-NCPK-04), 차종 매핑(AD-CTLG-09) 모두 "좌측 대상 목록 + 우측 체크리스트, 저장 시 전체 교체(delete+createMany)" 패턴을 그대로 반복 사용. `CLAUDE.md`가 명시한 "체크리스트류 매핑 테이블은 항상 전체 삭제 후 재생성" 원칙과 일치.
- **정렬순서 변경 UI**: 원래 스펙 문서는 CstItemMgmtPage(AD-CTLG-03)와 FaqMgmtPage(AD-CS-03) 둘 다 "드래그로 정렬"을 요구했지만, 두 화면 모두 항목 수가 10~20개 내외라 별도 DnD 라이브러리 없이 ▲▼ 인접 스왑 버튼으로 대체 — CstItemMgmtPage가 선례이고 FaqMgmtPage가 그 패턴을 그대로 재사용.
- **팝업 vs 독립 메뉴의 기준**: 스펙 문서(xlsx)에서 URL 경로가 `"-"`로 표시된 항목은 전부 팝업으로 구현되고 sidebar 메뉴 트리에서 제외됨(`menuConfig.ts` 헤더 규칙). 포인트 강제부여/차감, 쿠폰 발행, 업체 등록/상세가 모두 이 규칙을 따름.
- **원가(`supplyPrice`) 등 민감 정보 권한 분리**: AD-CTLG-05(상품 관리)에서 원가는 `SUPER_ADMIN`·`SETTLEMENT` 권한그룹에게만 노출 — `AdminAccount.permGroup` 기반의 필드 단위 접근 제어 사례.
- **admin 컨트롤러 명명 불일치 1건**: `companies.controller.ts`는 클래스명이 `CompaniesController`로 다른 16개 컨트롤러(`Admin*` 접두)와 다르지만 라우트는 동일하게 `/admin/companies` 아래에 있음 — 기능상 문제는 없으나 다음에 admin 컨트롤러를 만들 때 이름 규칙을 통일하려면 참고.

## 아직 실행 엔진이 없는 설정값 — 명시적으로 확인된 것들

- `MemberGradeRule`(AD-PNT-07): GOLD/SILVER/BRONZE 산정기준·혜택 값은 저장되지만, 실제로 회원 등급을 계산해서 부여하는 배치/트리거는 아직 없다.
- 포인트 유효기간: 관리 화면 자체가 없고(AD-PNT-03 삭제됨), 만료를 처리하는 엔진도 없다.
- 입찰 마감시간(`BID_DEADLINE_DAYS`): 화면은 없고 `bid-requests.service.ts`의 코드 상수로만 존재.
